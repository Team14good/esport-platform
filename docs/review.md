## 二、規格和設計的缺口（實作時會卡住）

### 1. 加鎖順序規則和「確認 → 晉級 → 賽事結束」的連鎖動作衝突

- **位置**：C:224、D:522、SP:94（AD-6）；C:245～249、D:525、D:529、D:673
- **問題**：
  - 規則是「同時需要兩種鎖時，先鎖賽事、再依 id 遞增鎖場次」。
  - 申訴期滿自動確認（C:245～249）先鎖本場 A，再由 `advance()` 把勝隊填入下一場 B。B 的 id 是隨機 UUID，可能比 A 小。
  - 決賽確認後還要把賽事轉為「已結束」，等於持有場次鎖時再要賽事列的鎖。
  - 取消資格（D:673）則是先鎖賽事、再依 id 鎖場次。

  兩條流程同時跑時，加鎖順序相反。推測 PostgreSQL 會偵測到死結並中止其中一個交易：發生機率不高，但主辦方的取消資格操作可能偶發失敗。
- **建議**：會連鎖到下一場或賽事狀態的流程（自動確認、處理申訴），一開始就先鎖賽事列，再依 id 遞增一次鎖住本場、下一場（與季軍賽）。`next_match_id` 不會變，可以事先讀出來。把這條寫進 AD-6 與 D 的 `advance()` 說明。

### 2. registration 沒有開放其他模組需要的查詢函式

- **位置**：D:101～103（`ensure_captain(team, account)`）、D:364～379（RegistrationService）、D:487、D:490、D:563、D:566、D:588、D:648～659；C:409（AD-2）、C:417（AD-10）
- **問題**：其他模組有三種需求，都要向 registration 取資料：
  - competition 的 `check_in()`、`upload_screenshot()` 與 disputes 的 `file_appeal()`、`file_report()`，都要判斷「這個帳號是不是某隊的隊長」。
  - `file_report()` 還要知道被檢舉隊伍的報名狀態（D:588）。
  - 公開對戰樹需要隊名。

  但 `ensure_captain()` 接收的是 registration 的 Team 實體，依 AD-2，其他模組拿不到 ORM 物件；RegistrationService 也只開放 `is_member()`、`next_waitlisted()`、`mark_status()`。D:648～659 的協作表也沒有 disputes → registration 這一列。照現有介面，這些功能要嘛違反 AD-1、AD-2 直接查表，要嘛做不出來。
- **建議**：
  - RegistrationService 補 `get_team(team_id) → TeamRead`（含隊名與隊員角色）與 `get_registration(team_id) → RegistrationRead`。
  - `ensure_captain()` 改收 TeamRead。
  - 協作表補 competition、disputes 呼叫 registration 的列。
  - CD 的 D-3 同步修改。

### 3. 對「棄權判定」的申訴成立時，沒有重賽的路徑

- **位置**：B:1628（申訴含棄權判定）、B:1644（更正＝重新輸入各局結果）、B:921（更正後 outcome 改為 played）、B:592～615（場次狀態圖）
- **問題**：如果主辦方查證後認定棄權判錯（例如臨時改時間沒通知到隊伍），合理的處理是重新比一次。但目前的「更正結果」只能重新輸入各局結果，狀態圖也沒有「申訴中 → 待開打」，主辦方只能自己編一個比分。
- **建議**：組內二選一，寫進 FR-31：
  - (a) 更正時多一個「重新比賽」選項：場次回到待開打，清除棄權判定與 outcome，重新設定時間與棄權期限；狀態圖加「申訴中 → 待開打」。
  - (b) 明確寫「棄權申訴只能維持原判，或改判另一隊棄權」，不提供重賽。

### 4. 抽籤時只為「第一輪」設定棄權期限，會漏掉兩支輪空隊伍在第二輪相遇的場次

- **位置**：B:1527（輪空隊伍由抽籤隨機決定）、C:232、D:524、SP:105、CD:160、CD:585
- **問題**：輪空位置隨機時，兩支輪空隊伍可能在第二輪直接相遇（例如 13 隊、3 個輪空）。這一場在抽籤當下兩隊就確定了，但文件只說抽籤時為第一輪呼叫 `start_forfeit_clock()`；之後設定棄權期限的只有 `advance()`、遞補與頂替。所以這一場的 `forfeit_deadline` 會一直是空的，worker 永遠不會對它判棄權。
- **建議**：把「抽籤時設定第一輪」改成「抽籤時為所有兩隊都已確定的場次設定」；或在 FR-20 規定輪空分散，讓輪空隊伍不會互相對上（見五-2）。

### 5. 取消賽事後，場次層級的定時工作沒有說要停

- **位置**：B:1395（FR-10）、C:150、D:529、EP:782
- **問題**：FR-10 只說取消後不再接受報名或登錄比分，EP:782 的檢查函式也只給報名與比分使用。賽事狀態圖保證「已取消」不會再轉換，但判棄權、申訴期滿自動確認、申訴逾期提醒、賽事開始，都是 worker 依各場次的期限挑出來的，文件沒有說要略過已取消的賽事。取消後仍可能判棄權、寄通知、推進晉級。
- **建議**：在 AD-7 與 D:529 寫明：worker 的場次層級工作先檢查賽事狀態，已取消或已結束的賽事一律略過。或者取消賽事時，一併清空各場次的期限欄位。

### 6. 送出報名後，選手的參賽資料能不能修改沒有定義

- **位置**：B:1454（FR-13）、B:1439～1446（FR-12）、B:1505～1507（FR-18）、EP:917
- **問題**：FR-13 的鎖定只寫「不能新增、移除或替換隊員」，沒寫遊戲 ID、段位、段位截圖能不能改：
  - 如果能改，主辦方審核的段位截圖可能在送出後被換掉。平均段位積分有快照，但截圖與段位沒有。
  - 如果不能改，FR-12 與 Story 3.2 都沒寫，實作的人無從得知。
- **建議**：FR-13 加一句「名單鎖定期間，選手的參賽資料也不能修改；被退回後解鎖」，並在 Story 3.2 加對應的驗收條件。

## 五、想討論的規則

1. 優先期內送出後撤回或被退回的學校，算不算「優先期有報名」（影響先搶期資格，B:1413）？被退回後在先搶期重送，送出時間要重新記錄嗎？快照在送出時寫入（B:547），會影響同分排序與先搶期判定。
2. 輪空位置要不要分散，避免兩支輪空隊伍在第二輪相遇？（B:1527；也能順便消除二-4）
3. 季軍賽的隊伍被取消資格時，依 FR-22 的一般規則，會由八強輸給它的隊伍頂替進季軍賽（B:1552）。這是想要的結果，還是讓季軍賽的對手直接輪空、獲得季軍？
4. 帳號的學校是必填嗎？ERD 畫成可為空（B:627），FR-1 寫「學校從學校清單選擇」（B:1290）。社群賽的非學生、平台管理員要怎麼處理？
5. 裁判沒出現，或兩隊都報到後遲遲沒開始時，主辦方能不能收回指派、改派或直接代登？要不要有逾時機制？目前 FR-26 只允許「未指派裁判」時代登（B:1595），改派也只出現在 FR-4 的晉級衝突（B:1334）。
6. 主辦方修改單一場次的時間，要不要限制不能晚於下一輪（B:1564～1565）？
7. 隊伍能不能解散、隊員能不能自己退出？目前只能由隊長移除隊員（B:1430），加入錯隊伍的人在同一賽事就無法再加入別隊；EX:627 也列為開放問題。
8. 提出檢舉的隊伍需要是什麼報名狀態？組隊中或已撤回隊伍的隊長能不能檢舉（B:1652）？
