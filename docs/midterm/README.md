## 重新產生 PDF 與 Word 檔

修改 Markdown、`figures/src/` 或 `meta.json` 後執行：

```bash
node docs/midterm/_build/build.mjs
```

- 只產生其中幾份：`--only A,C`
- 需要 Node 22 以上、本機的 Chrome 或 Edge，並且要能連網（從 CDN 載入 marked、mermaid、paged.js、docx）。
- Word 檔由 `_build/docx-writer.js` 產生，圖是從排版好的頁面擷取的 PNG（2 倍解析度），與 PDF 相同。直接在 Word 裡改的內容，下次執行排版程式時會被覆蓋；要保留的修改請改在 Markdown。
- 一般的圖用 Mermaid 撰寫。使用案例圖與泳道圖是自訂語法（說明在 `_build/usecase.js`、`_build/swimlane.js` 開頭），原始碼放在 `figures/src/<名稱>.usecase` 或 `.swimlane`，Markdown 以 `![說明](figures/<名稱>.png)` 引用。PDF 內直接排入向量圖；每次執行也會重新產生 `figures/<名稱>.png`，讓 GitHub、VS Code 預覽與轉 Word 時都看得到圖。修改原始碼後記得重新執行，PNG 才會更新。
- 執行結果會列出縮放比例低於 0.62 的圖（字會偏小），以及任何畫圖錯誤。
- `_build/html/` 是排版過程產生的中間檔，不進版控（已列入 `.gitignore`）。

## 2026-10-19 依審閱意見修訂（待組內確認；已寫回 PRD、架構骨幹、C／D 打底稿、Epic 與 UX）

修訂前的版本已自 repo 移除，需要時用 `git show b20d0dd:docs/midterm/_backup-2026-10-19/<檔名>` 取回。以下規則原本沒有定義或互相矛盾，本次先依下列方式寫進 A～D，組內討論後如有不同決定再改：

1. **用語**：裁判的動作改稱「送出系列結果」，「確認」只指場次進入「已確認」；B 的需求分組改稱「功能群」，與後端「模組」區分。
2. **輪空與雙方棄權**：場次新增「待開打 → 已確認（輪空）」與「已取消」（只用於季軍賽）；MATCH 新增 `outcome` 記錄結果類型。準決賽雙方棄權時，另一場準決賽的勝隊為冠軍、季軍賽取消、另一場準決賽的敗隊為亞軍、季軍從缺（沿用 Epic 5.6 的假設）。
3. **棄權計時暫停**：只暫停等待該申訴結果的場次，不是整輪；以「兩隊都確定才設定 `forfeit_deadline`」實作，期限為預定時間與兩隊確定時間較晚者加棄權時限。申訴逾期提醒以 `Appeal.reminded_at` 確保只提醒一次。
4. **每輪間隔**：遊戲新增「每局預估時間」，每輪間隔不得小於「棄權時限＋預設 BO × 每局預估時間＋申訴期」；某輪 BO 較大時，排程自動順延下一輪。
5. **賽事狀態**：新增「尚未開放」；報名開始與「第一個場次開放報到時轉為進行中」由 worker 執行。
6. **報名狀態**：補上待分配撤回、抽籤後候補直接轉為已參賽、待分配與候補可被取消資格。

## 2026-10-20 依 `docs/review.md` 討論後補充（待組內確認）

審閱意見與處理狀態見 `docs/review.md`。以下規則經討論決定，已寫進 A～D 與規劃文件：

1. **棄權申訴可重賽**：申訴對象是棄權判定、主辦方認定判錯時，可選「重新比賽」：場次回到待開打，清除棄權判定與報到紀錄，依新時間重新起算棄權期限（FR-31；場次狀態圖加「申訴中 → 待開打」）。
2. **送出後參賽資料鎖定**：名單鎖定期間，選手的遊戲 ID、段位與段位截圖也不能修改，被退回後解鎖（FR-13）。
3. **分輪 BO**：開放報名後到抽籤前可以修改（FR-9）。
4. **檢舉**：可檢舉待分配、正取、候補與已參賽的隊伍，介面補上對應的入口；提出檢舉的隊伍也須已送出報名（FR-32）。
5. **優先期有報名**：以優先期結束時仍為「已送出・待分配」的報名為準；被退回後重送時，快照與送出時間重新記錄（FR-15、FR-18）。
6. **輪空分散**：輪空位置平均分散，輪空數不超過 P ÷ 4 時兩支輪空隊伍不會在第二輪相遇（FR-20）。
7. **季軍賽隊伍被取消資格**：季軍賽由對手輪空獲得季軍（FR-22）。
8. **帳號學校選填**：註冊時可不選學校，參加校園賽時必須設定（FR-1、FR-13）。
9. **裁判改派**：送出系列結果前，主辦方可改派或收回指派，收回後代登（FR-4）。
10. **改場次時間**：新時間不得早於現在，也不得晚於勝隊要去的下一場（FR-23）。
11. **退出與解散隊伍**：名單鎖定前隊員可自行退出、隊長可解散隊伍，解散後報名轉為撤回（FR-41 改名為「隊員異動與解散隊伍」）。
12. **伺服器端檢查**：兩隊都報到後才能登錄比分（FR-26）；有一隊達到勝局門檻才能送出系列結果（FR-27）。
