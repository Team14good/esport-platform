- (decision) 簡介寫方案 A 電競賽事管理平台；方案 B 校園二手交易待組員決定，若改選 B 另開一份
- (event) 來源資料：docs/project-background.md（課程要求、範本摘要、A/B 方案內容）、Claude Docs 提案文件
- (decision) 用途＝課程評分專案，簡介對應 A 專案管理規劃的背景與問題、並作為 PRD 起點；嚴謹度依此校準，不需投資人等級
- (decision) 主要使用者＝主辦方；賽程由主辦方報名截止後抽籤決定（使用者經驗，且與 2024 大專盃規程「人工或電腦抽籤、無迴避」一致）
- (decision) 主打 LoL 與 VALORANT 兩款，但系統適用任何兩隊對戰遊戲
- (change) 使用者想串遊戲 API 取比分與選手 KDA；查證：VALORANT API 只開放給審核通過的 production key 且需 RSO 玩家授權，LoL dev key 每 24 小時過期、production 需審核 → 課程專案不可依賴 API，改為手動登錄、API 列加分/未來
- (change) 比賽結束需附選手 KDA（新需求，影響資料模型：每場每位選手 K/D/A）
- (event) 使用者自己打 LoL/VALORANT、對電競有興趣，但沒辦過比賽 → 問題段落以公開規程佐證，不靠推測
- (event) 查證 2024 第六屆大專盃電競錦標賽 VALORANT 規程：64 隊上限、同校多隊以牌位積分平均決定代表、名單 6 人提交後不得換、BO3 單淘汰、賽前 30 分鐘 Discord 檢錄、逾 15 分鐘未開始判棄權、結果以伺服器結算畫面為準由裁判紀錄並請選手自行截圖、申訴須賽後 30 分鐘內寄 email 申訴書
- (assumption) 與先前方案的落差：真實賽事由裁判紀錄結果，不是雙方隊長回報；先前『雙方回報＋不一致仲裁』規則需與使用者重新確認
- (decision) 比分流程採現實版：裁判登錄每局比分；隊長上傳結算截圖並可於賽後 30 分鐘內線上申訴；裁判長判定。取代原『雙方回報＋不一致仲裁』
- (decision) 選手 KDA 列為加分項目，必做只記比分
- (decision) 串遊戲官方 API 列為加分/未來，必做為人工登錄
- (decision) 採快速版：直接起草，推測處標 [假設] 供審閱
- (event) 完成簡介初稿（快速版），含 [假設]：小型賽事用表單與 Excel、Challonge/start.gg 未針對台灣校園規則、示範 32 隊、壓測 1000 人、願景；待使用者審閱
- (decision) 確認小型賽事目前多用 Google 表單與 Excel（移除假設標記）
- (decision) 同校限制：每校優先 1 隊（沿用大專盃規則）
- (decision) 申訴時限 30 分鐘、遲到判負 15 分鐘為系統固定預設，主辦方只能放寬、不能縮短
- (decision) 示範規模 32 隊、壓測 1000 人同時報名（確認，移除假設標記）
- (decision) 不做帶隊老師／領隊角色
- (decision) 願景：優化整個報名流程、以視覺化對戰樹呈現賽程與勝負晉級狀況，公開讓所有人即時查看
- (change) 套用 bmad-review structure/prose 審查建議 9 項（修正清單斷裂、去重、精簡、用詞統一）
- (event) 簡介定稿 status: final
- (change) 依 PRD 定稿同步：裁判長→主辦方、三階段名額分配、取消資格頂替改必做、新增平台管理員與季軍賽
