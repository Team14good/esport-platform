# FLOW — Experience Spine

> 本文件寫「怎麼運作」；「長什麼樣」（品牌、logo、配色、元件樣式）見 `DESIGN.md`。Token 以 `{colors.primary}` 形式引用 DESIGN.md。名詞一律照 PRD §3 名詞表（賽事／場次／局；輪空不叫種子；不用「比賽」泛稱）。需求內容不在此重述，只引用 FR／NFR／AD 編號。凡未經使用者決定的內容標 `[ASSUMPTION]`。

## Foundation

- **形式**：單一響應式網頁（PRD §6 不做原生 App）。375 px 寬起完全可操作（NFR-7）；觀眾旅程以手機為主（UJ-4）。
- **UI 系統**：shadcn/ui ＋ Tailwind CSS 4，React 19 ＋ TanStack Router（檔案路由 `src/routes/`）＋ TanStack Query（AD 技術堆疊）。行為規格只寫 shadcn／Radix 的差異；未提及的元件行為照 shadcn 預設。
- **語言與時區**：只有繁體中文介面；所有時間以 Asia/Taipei 顯示（AD-13）。錯誤訊息直接顯示 API 回傳的 `detail.message`（已是繁中）。
- **模式**：深色為預設，使用者可切換淺色（DESIGN.md〈Colors〉）。不跟隨作業系統偏好 [ASSUMPTION]；選擇存於 `localStorage` [ASSUMPTION]。
- **即時性**：對戰樹與場次頁每 5 秒輪詢（AD-14）；分頁在背景時暫停（TanStack Query 預設），回到前景立即重抓。結果確認後 10 秒內可見（FR-35）。沒有 WebSocket／SSE。
- **定時規則**：報名截止、優先期結束、棄權判定、申訴期滿由伺服器在到期後 1 分鐘內執行（NFR-4）。前端倒數只是顯示（見〈倒數與時間〉）。
- **權限**：前端依身分顯示／隱藏動作，但不是安全邊界（FR-5、NFR-5、AD-10）。
- **導覽骨架**：公開頁與個人頁用頂欄；主辦方賽事後台、平台管理後台用左側欄（使用者決定）。登入後以**身分切換器**進入各身分的首頁，不做統一儀表板（使用者決定，見〈身分切換器〉）。
- **示意圖**：只有 S3、S4 畫了示意圖（使用者決定）——[`mockups/key-s3-bracket.html`](mockups/key-s3-bracket.html)（對戰表：手機搜尋命中與找不到、桌機 32 隊）、[`mockups/key-s4-match.html`](mockups/key-s4-match.html)（場次頁：裁判登錄中、申訴期、手機觀眾）。其餘畫面只有文件。文件與示意圖衝突時，以文件為準。待更新的示意稿列在〈Open Questions〉。

## Voice and Tone

微文案規則。品牌語氣見 DESIGN.md〈Brand & Style〉。

| Do | Don't |
|---|---|
| 「送出報名」「報到」「抽籤」「送出系列結果」——按鈕用動詞＋PRD 名詞；「確認」只指場次進入「已確認」，不當作裁判動作的名稱 | 「Submit」「OK」「確定」等泛用字 |
| 「場次」「賽事」「局」 | 「比賽」泛稱、「matches」英文混用 |
| 「輪空」 | 「種子」「bye」 |
| 「候補第 3 位」 | 「排隊中」「等待中」 |
| 「10/18（六）19:00 起可報到」 | 「請稍後再試」（沒說何時） |
| 「送出後名單會鎖定，只有被主辦方退回才能修改。」——確認對話框寫後果 | 「確定要送出嗎？」 |
| 「申訴期剩 08:42」 | 「快點申訴！」、驚嘆號、表情符號 |
| 錯誤直接顯示伺服器 `detail.message` | 把伺服器訊息改寫成「發生錯誤」 |
| 空狀態一句事實＋最多一個下一步：「還沒有隊伍報名。」＋「複製賽事頁連結」 | 「這裡空空如也～」 |
| 對觀眾、選手、主辦方用同一種口吻：平實、短句、不加敬語堆疊 | 對不同身分換不同語氣 |
| 標頭與資訊列用「·」分隔（「32 強 · M3」）；「・」只用在狀態標籤（「待開打・可報到」） | 兩種點混用 |

## State Patterns

各狀態徽章的 tone 與圓點（對照為 [ASSUMPTION]；狀態色 token 本身為使用者決定）見 DESIGN.md〈Components〉Status badge 對照表；本節只寫行為。

### 賽事狀態（`TournamentStatus`，PRD §3）

| 狀態 | 觀眾（S1／S2）看到 | 帳號／隊長 | 主辦方（S27） |
|---|---|---|---|
| 尚未開放 | 報名開始時間與倒數（`muted`） | 「建立隊伍」停用，寫報名開始時間 | 報名開始倒數；S28 所有設定都能改（FR-9） |
| 開放報名 | 報名截止倒數、已正取隊數／名額 | 「建立隊伍」可用 | 優先期／報名截止倒數、「抽籤」（提前） |
| 報名截止 | 「抽籤準備中」 | 隊伍看到自己的正取／候補 | 「抽籤」（若尚未自動執行）；正取 < 2 時停用並提示延長報名或取消（FR-19） |
| 賽程已公布 | 對戰表分頁成為預設 | 第一場時間與對手 | 指派裁判、修改場次時間 |
| 進行中 | 對戰表為預設分頁 | 下一場倒數 | 待處理申訴／檢舉數 |
| 已結束 | Podium 置頂（冠軍、亞軍、季軍） | 唯讀 | 唯讀；檢舉入口消失（FR-32） |
| 已取消 | Page banner（destructive，〈固定介面字串〉），資訊唯讀（FR-34） | 所有動作停用 | 唯讀 |

### 場次狀態（`MatchStatus`，PRD §3）＋介面子狀態

| 狀態 | 場次頁（S4）行為 |
|---|---|
| 待開打 | 顯示預定時間；Check-in panel：隊長看到停用的「報到」、可報到時間與報到開放倒數；兩隊尚未都確定時不開放報到（FR-24） |
| 待開打・可報到（介面子狀態） | Check-in panel：隊長「報到」可用；顯示雙方報到狀態與距預定開始倒數；過預定時間後改為棄權期限倒數 |
| 待開打・可開始（裁判端，FR-24） | 只在 Score entry panel 顯示「可開始」 |
| 進行中 | 已登錄的局即時出現（輪詢）。何時進入見下方「待開打 → 進行中」 |
| 申訴期 | 系列比分＋申訴期倒數；兩隊隊長「提出申訴」可用（裁判、主辦方、觀眾沒有此動作）；勝隊隊長可上傳結算截圖；**不顯示晉級** |
| 申訴中 | 「申訴處理中」，不顯示晉級（FR-36）；不顯示申訴內容給觀眾 [ASSUMPTION] |
| 已確認 | 勝隊晉級；若經申訴處理，顯示處理結果（維持原結果／更正結果）[ASSUMPTION] |
| 棄權計時暫停（介面子狀態） | 見〈倒數與時間〉暫停（FR-25、FR-31） |
| 已取消 | 只用於準決賽沒有產生勝隊時的季軍賽（FR-21）：狀態徽章「已取消」，沒有比分與任何動作；對戰樹上的呈現見〈對戰樹〉邊界狀態 |

**待開打 → 進行中**：PRD §3 未定義觸發事件；本文件採裁判（或代登的主辦方）第一局登錄成功時轉換，在此之前即使兩隊都已報到仍是待開打（裁判端顯示「可開始」）[ASSUMPTION]，待回補（Open Questions 26）。判棄權的場次不經過進行中，直接進入申訴期（FR-25）。

**待開打 → 已確認（輪空）**：對手位置確定不會有隊伍時（前一場雙方棄權，或退賽、取消資格後無人遞補），系統直接確認、有隊伍的一方晉級（FR-21）；S4 沒有比分，該隊帶「輪空」標記。

**申訴中 → 待開打（重新比賽）**：判棄權的場次經申訴後安排重新比賽時（FR-31），S4 回到待開打，頁首下方寫「申訴後重新比賽」與新時間，報到重新開始 [ASSUMPTION]。

對戰表標記（FR-35）：淘汰（沒有文字標籤，樣式見 DESIGN.md〈Components〉Bracket match card）、輪空、棄權、取消資格、退賽、冠軍／亞軍／季軍（Bracket mark tag；邊界狀態見〈對戰樹〉）。

### 報名狀態（`RegistrationStatus`）

完整列舉與轉換表見期中文件 B 參、四（二）的報名狀態圖：「組隊中」「已送出・待分配」是正式狀態（2026-10-16 定案）。下表是各狀態在介面上的呈現；「遞補」是介面標籤，對應轉為正取或已參賽的候補。

| 介面標籤 | 何時 | 隊伍看到（S12／S17） |
|---|---|---|
| 組隊中 | 尚未送出 | Roster list 顯示每人完成度；不符合送出條件時，「送出報名」停用並逐項列出缺什麼（FR-13） |
| 已送出・待分配 | 優先期內送出 | 「優先期結束後分配名額」＋優先期結束倒數 |
| 正取 | 分配結果 | 抽籤前顯示報名截止倒數；可退賽 |
| 候補 | 分配結果 | 有順位時「候補第 N 位」（使用者決定）；照當下規則會被略過、沒有順位時「候補・目前不在遞補順序中」，徽章下方一行 `muted` 原因 [ASSUMPTION]（順位規則見 PRD FR-17，原因字串見〈固定介面字串〉）。兩種都附當下階段的遞補規則說明（FR-17）；只有該隊成員看得到 |
| 遞補 | 候補轉正取 | 「已遞補為正取」＋通知 |
| 退回 | 主辦方退回（FR-18） | 退回原因；名單解鎖，可修正重送（報名期間內） |
| 撤回 | 抽籤前退賽（FR-17），或組隊中被隊長解散（FR-41） | 唯讀 |
| 退賽 | 抽籤後、第一場開打前退賽（FR-17） | 唯讀；遞補隊伍接手對戰表上的位置 |
| 已參賽 | 抽籤後、對戰表上有位置（UJ-2） | 下一場對手與時間 |
| 取消資格 | FR-33 | 處理理由 |

## Interaction Primitives

- **點擊／點按為主**。沒有拖曳、沒有滑動手勢、沒有自訂鍵盤快捷鍵 [ASSUMPTION]。
- **伺服器為準**：狀態只由伺服器改變，前端不自行改狀態，倒數只是顯示。送出一律等伺服器回應再更新畫面；報名、比分不做 optimistic update（結果由伺服器判定，NFR-1）。併發衝突（如名額剛好用完）照伺服器結果顯示，例如送出後直接告知「候補第 N 位」（FR-15、NFR-1）。介面先停用的動作只是提示，伺服器仍是最終判定（AD-10）；被伺服器拒絕時照實顯示原因（`detail.message`）。
- **確認**：所有不可逆動作走 AlertDialog（Component Patterns 列表）；可逆動作不確認。
- **表單**：送出時驗證；建立賽事表單選遊戲後自動帶入預設值，主辦方可改；只能延長不能縮短的欄位（棄權時限、申訴期、每輪間隔）在 S28 的輸入下限＝目前值（FR-9）。
- **清單**：分頁，不做無限捲動 [ASSUMPTION]。
- **分享**：邀請連結、賽事頁、場次頁都是可直接分享的網址；對戰樹的隊伍搜尋不寫入網址（使用者決定收斂範圍）。
- **重新整理不遺失狀態**：清單的分頁與篩選寫在 URL 查詢參數 [ASSUMPTION]；對戰樹隊伍搜尋除外。
- **禁止**：Dialog 疊 Dialog、只在 hover 才出現的動作（手機無 hover）、無限捲動、播放音效、成就徽章、抽籤動畫或戲劇化揭曉（對戰表公布時直接出現＋通知）[ASSUMPTION]、未登入時的註冊彈窗（觀眾不需註冊，UJ-4）。

## Accessibility Floor

**使用者決定延後無障礙設計。** 本版不設 WCAG 等級目標，也不宣稱符合任何標準；色彩對比未驗證。僅記錄由 shadcn／Radix 自動繼承、不需額外工作的行為：

- Dialog／AlertDialog／Sheet／DropdownMenu／Popover／Tabs 的焦點鎖定、`Esc` 關閉、方向鍵導覽與 ARIA 屬性（Radix）。
- 焦點外框使用 `{colors.ring}`（shadcn 預設 focus-visible 樣式）。
- 原生表單元素的 label 關聯（shadcn `Form`）。

### 對戰樹（Bracket）

S3 是 UJ-2、UJ-3、UJ-4 高潮步驟所在的畫面。

示意：[`mockups/key-s3-bracket.html`](mockups/key-s3-bracket.html)——(a) 手機 UJ-4 高潮（搜尋「清大 Hydra」）、(c) 手機找不到、(b) 桌機 1280 px 完整 32 隊。

**版型**
- 每輪一欄，由左（第一輪）到右（決賽），欄頭為輪次名（例：32 強、16 強、8 強、4 強、決賽）。連接線把兩場接到下一輪的一場。
- **場次編號** [ASSUMPTION]：依輪次、同輪由上到下連續編號（32 隊：32 強 M1～M16、16 強 M17～M24、8 強 M25～M28、4 強 M29～M30、決賽 M31）；只編實際存在的場次（輪空不佔編號，FR-20 場次數）。季軍賽排在最後（32 隊時為 M32），但介面一律顯示「季軍賽」，不顯示編號。待定列以編號指向來源場次（字串見〈固定介面字串〉）。
- **桌機**：欄寬與尺寸見 DESIGN.md〈Layout & Spacing〉；32 隊不需橫向捲動，頁面往下延伸。只有對戰樹總寬超過容器時才橫向捲動 [ASSUMPTION]。
- 季軍賽放在決賽下方，獨立一張卡、標頭「季軍賽」[ASSUMPTION]。已結束時 Podium 在對戰樹上方列出冠軍、亞軍、季軍 [ASSUMPTION]，決賽與季軍賽卡的隊伍列加名次標記。
- 不顯示任何種子或籤位編號（不做種子排序）。

**邊界狀態**
- **沒有季軍賽**（FR-20：正取少於 4 隊）→ 不顯示季軍賽卡；Podium 只列冠軍、亞軍。
- **雙方棄權**（FR-25）→ 該場卡兩列都套淘汰樣式、各帶「棄權」標記（DESIGN.md〈Components〉Bracket match card）；下一輪原本等它勝者的位置顯示「—」＋「輪空」標記，對手照輪空晉級呈現 [ASSUMPTION]。發生在準決賽時（FR-21：另一場準決賽的勝隊以輪空成為冠軍；季軍賽取消，場次狀態「已取消」；另一場準決賽的敗隊為亞軍，季軍從缺）：決賽卡只有一隊、另一列「—」＋「輪空」，該隊帶「冠軍」標記；季軍賽卡保留、標頭徽章「已取消」（`{colors.muted-foreground}`），兩列灰色 [ASSUMPTION]；Podium 列冠軍、亞軍，不列季軍。

**場次卡**（Bracket match card；各狀態樣式見 DESIGN.md〈Components〉）
- 已確認：系列比分，勝隊與淘汰隊各套對應樣式。未開打：隊伍名＋預定時間；隊伍未定時顯示待定列（如「M4 勝者」）。
- 申訴期／申訴中：比分顯示，但勝隊**不**出現在下一輪（FR-29、FR-36）。
- 輪空、棄權、取消資格、退賽以 Bracket mark tag 標示（FR-35）。退賽或尚未出賽即被取消資格（FR-17、FR-22）：遞補隊伍出現在原位置；沒有候補時對手以輪空晉級呈現。已贏過至少一場後被取消資格（FR-22）：頂替的隊伍出現在該隊原本的位置，更早的場次結果不變。
- 點卡片 → S4。

**隊伍搜尋**（使用者決定）
- 對戰樹上方的輸入框，只搜尋**隊名**（學校是個資，不搜、不顯示，NFR-6）。輸入即篩選（不需按 Enter），不分大小寫、部分符合即可。
- 命中後：該隊在每一輪出現的列以 `{colors.search-highlight}` 標示，連接線同色，形成**晉級路徑**。
- **虛線列**：只有一列，即下一輪場次卡上，留給該隊目前未確認場次（未開打、進行中、申訴期或申訴中）勝者的待定列（例如清大 Hydra 在 8 強 M26，4 強 M29 的「M26 勝者」列）[ASSUMPTION]。該隊已淘汰、已是冠軍，或下一輪位置已由它填入時，沒有虛線列。
- 自動橫向捲動到該隊目前最遠的一輪。右側顯示命中數「找到 N 隊」；多隊命中時可用上一隊／下一隊切換。
- 清除（✕）回到完整對戰表。
- **找不到**：零結果時命中數為「找到 0 隊」，對戰樹不高亮任何列，並在搜尋框下方顯示「對戰表上沒有符合的隊伍。候補、已撤回或被退回的隊伍不會出現在對戰表上。」[ASSUMPTION]；不清除使用者輸入。
- **尚未抽籤**：S3 顯示〈通用狀態〉的「空：尚未抽籤」，搜尋框不顯示（沒有可搜尋的對戰表）。

**手機（375 px）**（使用者決定：橫向捲動＋隊伍搜尋）
- 對戰樹容器橫向捲動，不縮放、不做捏合縮放。
- **固定**：搜尋框在對戰樹的橫向捲動容器之外，不隨橫向捲動移動。垂直捲動時，搜尋框與輪次欄頭合成一條固定在視窗頂端；頂欄與賽事分頁（總覽／對戰表／正取隊伍）照常捲走 [ASSUMPTION]。「找不到」說明文字不固定。

**更新**
- 輪詢見〈Foundation〉即時性；有變動的場次卡處理見〈通用狀態〉輪詢重抓。保留使用者的捲動位置與搜尋高亮，不跳動。

| 左（主內容） | Score display；各局列表（「第 N 局」＋比分；裁判／代登主辦方看到的是 Score entry panel，取代公開列表）；結算截圖（送出後） |
| 右（`{spacing.match-aside-width}`） | 依狀態的倒數與動作：待開打為 Check-in panel（含報到倒數與「報到」）；申訴期為申訴期倒數＋「{絕對時間} 截止」＋（兩隊隊長）「提出申訴」；離開待開打後 Check-in panel 收起成兩隊報到時間。最下方為同輪其他場次 |

**`< lg` 單欄堆疊順序** [ASSUMPTION]：先頁首與 Score display，再來是**目前的動作區**（裁判：Score entry panel；待開打：Check-in panel；申訴期：申訴期倒數與「提出申訴」），之後依序為各局列表、結算截圖、兩隊報到時間、同輪其他場次。理由：手機上，下一步要按的按鈕與正在流逝的時間要在第一屏（DESIGN.md〈Elevation & Depth〉「最亮的地方應該是使用者下一步要按的按鈕」、〈Layout & Spacing〉觸控）；觀眾在申訴期也先看到倒數，才知道為何還沒晉級。

**依身分的差異**

| 身分 | 看到的動作 |
|---|---|
| 觀眾（含未登入） | 無；各局、系列比分、倒數、結算截圖、同輪其他場次 |
| 該場兩隊隊長 | 待開打「報到」；申訴期「提出申訴」（→ S21）；勝隊隊長在系列結果送出後另有結算截圖上傳（S22） |
| 被指派裁判／未指派時的主辦方 | Score entry panel（S24）；沒有「提出申訴」 |

示意稿與本文件的差異列在〈Open Questions〉示意稿待更新。

### 比分登錄（S24）

Score entry panel 的行為；位置見〈場次頁（S4）〉，視覺見 DESIGN.md〈Components〉Score entry panel。

- **誰看得到**：只有被指派裁判，或未指派裁判時代登的主辦方（FR-26）。看得到面板的人，左欄不再另外顯示公開的各局列表（面板的每局列就是列表）[ASSUMPTION]。
- **欄位**依比分型態：`win_loss` 為兩個隊名切換鈕、`rounds` 為兩個數字框；平手不能送出（FR-26）。
- **存檔模型**：每局按該列「登錄」即送伺服器（D-4 `MatchService.record_game`），成功後該局對所有人可見（輪詢）。同一時間只有一列可在編輯中 [ASSUMPTION]。

| 狀態 | 面板行為 |
|---|---|
| 兩隊報到前 | 面板停用，寫「等待雙方報到」 |
| 兩隊都已報到（待開打・可開始） | 標題旁顯示「可開始」（FR-24） |
| 第一局登錄成功 | 場次轉為進行中（見〈State Patterns〉場次狀態），「可開始」消失 [ASSUMPTION] |
| 列：未存 | 輸入欄位＋「登錄」；送出中停用該列，避免同一局重複送出（NFR-1） |
| 列：已存 | 文字比分＋「已登錄」＋「修改」 |
| 列：修改中（送出前，FR-27） | 該列回到輸入框；「登錄」重新送出、覆寫該局結果，或「取消」恢復原值 [ASSUMPTION]（覆寫走同一方法或另開方法見 Open Questions 23） |
| 系列進行中 | 「系列結果預覽」由已存的各局計算，不含未送出的輸入 |
| 一隊達勝局門檻 | 「新增一局」消失（FR-26） |

| 已送出（唯讀，FR-27） | 標籤改「系列結果」，顯示送出者與送出時間（`Match.submitted_by`、`submitted_at`）；兩者只在面板（裁判、主辦方）顯示，公開的各局列表不顯示 [ASSUMPTION]。送出後場次為申訴期，尚未確認 |

### 身分切換器（Identity Switcher）

使用者決定：登入後以身分切換，不做統一儀表板。

**身分來源**（一個帳號可同時擁有多種，PRD §3）

| 身分 | 何時出現 | 首頁 |
|---|---|---|
| 瀏覽賽事 | 永遠 | S1 |
| 我的隊伍（選手／隊長） | 加入或建立任一隊伍後 | S12 |
| 裁判 | 接受任一裁判邀請後（多個賽事合併為一個項目）[ASSUMPTION] | S13 |
| 主辦方後台 | 主辦方申請核准後 | S25 |
| 平台管理 | 平台管理員帳號 | S35 |

隊長不是獨立身分：同一帳號在 A 隊是隊長、B 隊是選手，差異只在 S17 的可用動作（PRD §3）。

**行為**
- 頂欄右側 `DropdownMenu`：列出擁有的身分，目前身分標示；底部「帳號資料」「登出」。
- 登入後：有 `redirect` 參數（例如從邀請連結過來）→ 回該頁；否則擁有 1 種身分 → S1；≥ 2 種 → 第一次到 S11，之後直接到上次使用的身分首頁（存於 `localStorage`）[ASSUMPTION]。
- 切換身分只換導覽骨架與首頁（頂欄 ↔ 側欄），不改權限；任何頁面都可以直接用網址打開，權限由伺服器判定。
- 新身分出現時（例如申請核准、接受裁判邀請），身分切換器會出現新項目（FR-3：核准後立即可建立賽事）：接受裁判邀請後當下重新取得身分清單；申請核准則在下次輪詢到核准通知時（最多約 30 秒）重新取得 [ASSUMPTION]。
- 登出：清除登入狀態，回 S1，不需確認 [ASSUMPTION]。

### 通知（Notifications）

**事件與對象**照 FR-37 對象表，本文件不重述。每個事件同時產生站內通知與 Email。

**站內（S14）**
- 頂欄鈴鐺顯示未讀數，超過 99 顯示「99+」[ASSUMPTION]。未讀數每 30 秒輪詢一次 [ASSUMPTION]（AD-14 的三種輪詢之一）。
- 點鈴鐺開 `Popover`：最新 8 則 [ASSUMPTION]，底部「查看全部」→ `/notifications`。
- 點一則通知：標為已讀並導向它的 `link`（賽事、場次或報名，FR-38）。
- 新通知在列表最上方（FR-38）；每則顯示 `title`、相對時間（「3 分鐘前」），並以一行小字顯示絕對時間（需 `Notification.created_at`，見 Open Questions 13）。
- 列表分頁，每頁 20 則 [ASSUMPTION]。

**Email（S37）**
- 主旨＝通知 `title`；內文一段說明＋一個按鈕連到同一個 `link`；寄件者名稱「FLOW」[ASSUMPTION]。版型細節見 Open Questions 19。
- 寄送失敗不影響主流程、對使用者不可見（FR-37）。
- 不提供通知偏好設定（關閉某類通知）[ASSUMPTION]。

### 倒數與時間（Countdown & Time）

使用者決定：顯示報名截止、報到、棄權時限、申訴期的倒數。

**顯示格式**（Asia/Taipei，AD-13）
- 絕對時間：`10/18（六）19:00`；跨年才加年份 [ASSUMPTION]。不標示時區（單一時區產品）[ASSUMPTION]。
- 相對倒數：24 小時以上「剩 2 天 5 小時」；1 小時以上、未滿 24 小時「剩 5 小時 12 分」；未滿 1 小時 `mm:ss` 每秒跳動。
- 倒數下方永遠以一行小字顯示絕對截止時間，格式「{絕對時間} 截止」[ASSUMPTION]。

**哪裡顯示哪個倒數**

| 倒數 | 目標時間 | 顯示於 | 變體 |
|---|---|---|---|
| 報名開始 | `registration_start` | S2、S27（尚未開放的賽事） | `muted` |
| 優先期結束 | 優先期結束時間 | S2、S17（已送出・待分配）、S27 | `muted` |
| 報名截止 | `registration_end` | S2、S12、S17、S27 | 剩餘超過 24 小時 `muted`；最後 24 小時 `appeal` [ASSUMPTION] |
| 報到開放 | `scheduled_at` − 30 分 | S4、S12 | `muted` |
| 距預定開始／棄權期限 | `scheduled_at`，之後 `forfeit_deadline`（兩隊都確定時才有值） | S4、S12（隊長）、S24 | 預定時間前 `live`；過預定時間後 `appeal` |
| 申訴期 | `appeal_deadline` | S4（所有人）、S3 場次卡標頭（只顯示徽章） | `appeal`（唯一帶進度條的倒數） |
| 申訴處理期限 | 等待這個結果的下一場的預定開始時間（決賽與季軍賽為申訴提出後 1 小時） | S32、S27 待辦 | 剩餘超過 1 小時 `muted`；最後 1 小時 `destructive`（對應 FR-31 提醒）[ASSUMPTION] |

**到期行為**（NFR-4：伺服器最多延遲約 1 分鐘）
1. 倒數歸零的瞬間，對應的使用者動作按鈕（例如「提出申訴」「送出報名」）立即停用，停用原因寫「已截止」。
2. 倒數位置改為「已截止 · 系統處理中」＋小 spinner（前端不改狀態，見〈Interaction Primitives〉伺服器為準）。
3. 頁面每 5 秒重抓一次，直到伺服器回傳新狀態（最多 2 分鐘）[ASSUMPTION]（AD-14 的三種輪詢之一）；之後顯示「處理時間比預期長。重新整理頁面查看最新狀態。」
4. 使用者在臨界點送出而被伺服器拒絕時，照實顯示 `detail.message`（例如申訴期已結束）。

**時鐘**：倒數以使用者裝置時間計算，不另做伺服器時間校正（架構未提供）[ASSUMPTION]；狀態轉換見上方到期行為。

**暫停**（FR-25、FR-31）：前一場申訴未處理時，只有等待該結果的場次（準決賽申訴時含季軍賽）暫停，同一輪的其他場次照常；該場兩隊尚未都確定、伺服器沒有 `forfeit_deadline`，報到與棄權倒數改顯示「計時暫停」，S4 的 Check-in panel 整個停用，並顯示計時暫停的 Page banner（〈固定介面字串〉）。申訴處理完成後依伺服器重新起算的時間繼續（棄權期限＝max（預定開始時間, 處理完成時間）＋棄權時限，FR-25）。

## Key Flows

### UJ-1. 小安開辦一場 32 隊的校際特戰英豪盃。

小安，某大學電競社社長，以前用 Google 表單與 Excel；第一次來，沒有帳號。

1. 小安在 S1 點「註冊」→ S5 → S7 提示收信；在 Mailpit 點驗證連結，回到 S1。
2. S1 的 Page banner「想辦賽事？申請成為主辦方」→ S15，填社團名稱、選擇學校送出；狀態「待審核」。
3. 平台管理員在 S35 核准。小安收到通知（S14＋Email）；身分切換器出現「主辦方後台」→ S25。
4. S25「建立賽事」→ S26：選特戰英豪，先發 5、替補 1、BO3 自動帶入；填名額 32、報名開始與截止時間、優先期 1 天、開賽日期、每輪間隔、賽事模式（校園賽）；展開「分輪 BO」把決賽改 BO5。送出 → S27，報名開始時間未到時狀態為「尚未開放」，到時自動變「開放報名」，「查看賽事頁」連到 S2。
5. 報名期間在 S29 查看報名；點某隊開段位截圖檢視器，發現截圖造假 → 「退回報名」填原因（AlertDialog）。優先期倒數在 S27 走完後，S29 出現正取／候補分組。
6. **高潮：** S27 的報名截止倒數歸零 →「已截止 · 系統處理中」→ 1 分鐘內狀態變「賽程已公布」（或小安提前按「抽籤」，AlertDialog 寫明「抽籤只能執行一次，會立即結束報名」）。S2 的對戰表分頁出現 32 隊單淘汰對戰樹，所有隊長收到通知。
7. 結果：小安到 S30 依輪次為每場指派裁判，到 S31 複製裁判邀請連結。

失敗／例外：
- 正取不足 2 隊 → 「抽籤」停用並說明，提供「延長報名」（S28）或「取消賽事」。
- 抽籤前想放寬 → S28 延長報名期間或提高名額；哪些欄位能改見〈動作停用條件〉S28（FR-9）。
- 必須取消 → S27「取消賽事」→ AlertDialog（標題「取消賽事」，內文寫後果：「所有已報名隊伍的隊長與選手會收到通知；賽事資訊改為唯讀，無法復原。」[ASSUMPTION]）→ 確認後 S27 唯讀，S1／S2 顯示「已取消」徽章與 Page banner（FR-10）。
- 改場次時間 → S30 該場「修改時間」→ Dialog 選新時間 [ASSUMPTION] → 送出後兩隊與裁判收到通知（FR-23）；停用條件見〈動作停用條件〉S30。
- 抽籤後某隊在第一場前退賽 → 依 FR-17 調整（呈現見〈對戰樹〉場次卡）。

### UJ-2. 阿哲帶隊報名，隊伍出現在對戰表上。

阿哲，某科大特戰英豪隊長，在 Discord 看到公告連結；已有帳號並登入。

1. 阿哲點連結到 S2：總覽顯示「開放報名」、報名截止倒數、正取隊數／名額。他按「建立隊伍」→ S16 輸入隊名 → S17。
2. S17 的 Invite link field 按「複製連結」，貼到隊伍群組。
3. 隊友點連結 → S19；沒帳號的先 S5 → S7，驗證後自動回到 S19 → 「加入隊伍」。
4. 每位隊員在 S17 按「填寫我的資料」→ S18：遊戲 ID、段位（從對照表選）、上傳段位截圖。S17 的 Roster list 逐人顯示完成／未完成，下方顯示平均段位積分（含替補）。
5. 名單人數達先發人數（5 人）、全員資料完成、隊員同校 →「送出報名」可用（FR-13）；AlertDialog 說明名單會鎖定 → 送出。優先期內顯示「已送出・待分配」＋優先期結束倒數；先搶期（優先期結束後先到先得，PRD §3）內當下顯示「正取」、「候補第 N 位」或「候補・目前不在遞補順序中」＋原因。
6. **高潮：** 抽籤完成，鈴鐺未讀數 +1。阿哲點通知 → S3，在隊伍搜尋框輸入自己的隊名，整條晉級路徑亮起：第一輪對手與時間就在高亮路徑起點。
7. 結果：S12 顯示隊伍「已參賽」，並顯示下一場的報到開放倒數。

失敗／例外：
- 同校另一隊平均段位積分較高、在優先期成為代表隊 → 先搶期內 S17／S12 顯示「候補・目前不在遞補順序中」＋原因與代表隊退出時的補充（〈固定介面字串〉）；報名截止後依平均段位積分參加截止補位，沒補上則依報名截止後的規則顯示順位或原因；遞補時收到通知，狀態變「已遞補為正取」。
- 阿哲懷疑另一隊有隊員不同校 → S2「正取隊伍」該隊列「檢舉」→ S20 填說明附截圖 → 送出。主辦方在 S33 取消資格後，阿哲收到處理結果；S3 上該隊標「取消資格」，並依 FR-22 調整（呈現見〈對戰樹〉場次卡）。
- 名單鎖定前，隊長可在 S17 移除隊員或轉讓隊長（見 Roster list）。

### UJ-3. 開賽日：小芸執法阿哲隊的第一輪 BO3。

小芸，電競社幹部，被小安找來當裁判。

1. 小安在 S31 複製裁判邀請連結傳給小芸。小芸開 S23 → 先 S5 → S7 → 回 S23「接受邀請」。身分切換器出現「裁判」。
2. 小安在 S30 把第一輪這場指派給小芸；小芸收到通知 → S13，該場在列。
3. 開賽前 30 分鐘，兩隊隊長在 S4 的 Check-in panel（或從 S12 進入）按「報到」；更早按的人看到「{絕對時間} 起可報到」。兩隊都報到後，小芸在 S24 看到「可開始」。
4. 每打完一局，小芸在 S24 登錄（特戰英豪為 `rounds`：輸入 13:11 這類回合比分；平手不能送出）。S4 對所有觀看者即時（輪詢）出現每局結果。
5. 一隊拿下第 2 勝，「新增一局」消失，預覽顯示系列結果 2:1。小芸按「送出系列結果」（AlertDialog）→ 面板唯讀，S4 出現申訴期 30:00 倒數。
6. 勝隊隊長在 S22 上傳結算截圖。
7. **高潮：** 申訴期倒數歸零 →「已截止 · 系統處理中」→ 1 分鐘內場次變「已確認」，S3 上勝隊晉級到下一輪；開著頁面的人 10 秒內看到更新。
8. 結果：下一輪對位確定，兩隊隊長收到下一場對手與時間的通知。

失敗／例外：
- 過了預定時間，到棄權期限仍有一隊未報到 → 該隊標「棄權」，進入申訴期。
- 阿哲認為比分有誤 → 申訴期內在 S4 按「提出申訴」→ S21 → 場次變「申訴中」，S3 不顯示晉級。小安在 S32 選「維持原結果」或「更正結果」（重輸各局、系統重算）並填理由 → 場次「已確認」，晉級觸發，兩隊收到理由。
- 小安若在等待這個結果的下一場開始前 1 小時仍未處理 → S27 待辦與 S32 倒數轉為 Countdown `destructive` 變體，並收到提醒（FR-31）。

### UJ-4. 小美在通勤時查看比賽打到哪裡。

小美，參賽學校的同學，沒參賽、沒登入，在捷運上用手機。

1. 小美點社群分享的連結 → S2（375 px）。賽事「進行中」，預設顯示對戰表分頁。
2. 她在隊伍搜尋框輸入學校隊伍的隊名；對戰樹自動捲到該隊目前最遠的一輪，晉級路徑整條高亮，已淘汰的隊伍都是灰色。
